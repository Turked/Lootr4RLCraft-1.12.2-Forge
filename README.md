# Lootr4RLCraft

Lootr4RLCraft is an independent Forge mod by **MechGaming** for personal loot inventories in Minecraft Java Edition 1.12.2. The target pack is RLCraft 2.9.3 with Forge 14.23.5.2860 and Java 8. The project is unaffiliated with the creators of Lootr, RLCraft, and Minecraft. The name is provisional for development.

## Development status

For a fresh Windows checkout, use the setup guide and the saved development checkpoint. They cover the Java 8 toolchain, local modpack path, disposable server and the next connected-client test. [Windows setup](DEVELOPMENT_SETUP.md) · [Development checkpoint](DEVELOPMENT_CHECKPOINT.md)

The server enrolls supported structure-generated chests, barrels, cabinets and chest minecarts. It preserves their original models and generates or assigns a persistent inventory for each player. Other inventories keep their native behavior. New fixed-content records preserve the original slot layout and item NBT. The unopened indicator is gold, the opened indicator is gray, and targeting a managed container displays the viewer’s state in the HUD.

This is a development build. The qualification report lists the tested versions and environments, the original failed Ruins sample and outstanding acceptance cases. [Verification report](VERIFICATION.md) · [Rendered RLCraft comparisons](qa/evidence/client/README.md)

## Build and try in a disposable world

1. Install JDK 8 and run `./gradlew build` (`.\gradlew.bat build` on Windows) from this directory. The first build needs access to Forge's Maven repository and other upstream development downloads. The build runs the storage regression test. `./gradlew lootStorageTest` runs it on its own.
2. Put `build/libs/Lootr4RLCraft-0.2.0-dev.jar` in `mods` on a test client and server running the same pack version. Keep one Lootr4RLCraft JAR in each `mods` folder. Use a clean RLCraft 2.9.3 copy with the pack's bundled launch setup. Lootr and Lootr: RLCraft Edition are separate mods and are excluded from the test setup. Lootr4RLCraft has no extra runtime dependency beyond Forge.
3. New installations enable `B:registerNewChests=true` in `config/lootr4rlcraft.cfg`. If you used the first development build, change its saved `false` value to `true` and restart. Registration applies to new generation. `includeTrappedChests` narrows new registration. `generatedFixedChests` preserves prefilled items for each player in newly generated chests that have no retained loot table. Set it to `false` to automatically register only chests that retain native loot tables. The local `visuals` section controls trim and colors.
4. Generate an unexplored area or use the commands below for an existing test inventory. Test with multiple players and save and restart between visits. Player-created storage stays ordinary until an administrator explicitly converts it. Structures generated by earlier builds retain their saved state.

Discovery observes actual generator-created tile identities through population, additional world generators, Recurrent Complex structure events, Ruins template events and Doomlike chest events. It has no fixed four-chunk reach limit. Locks finishes its native generation against the original contents before private registration proceeds.

## Administrator commands

Commands require operator permission or single-player cheats. A loaded chest minecart can be addressed with its UUID as the single argument following the action. Point at the chest within five blocks and run one of these commands. Each command also accepts `x y z` coordinates in the sender's dimension, with all relevant chunks already loaded.

- `/lootr4rlcraft inspect` reports the block, tile, saved loot information and conversion eligibility.
- `/lootr4rlcraft convert` converts an eligible inventory that still retains its original loot source. The installed container's generation method is used with the player's context, preserving native table rules, seeds and special algorithms such as Charm's loot-size behavior.
- `/lootr4rlcraft convert-fixed` explicitly converts the chest's current contents into the initial contents for each player. Use it for prefilled structure chests or test chests whose loot table has already been consumed. Each player starts with those same items in the same slots. This command also allows administrators to convert deliberately placed storage. Back up a played world before using it on valuable items.

The commands report refusals for unsupported sources or unavailable chunks. Existing containers are converted only by administrator selection. Connected chests and cabinets are converted together where the installed container exposes its pairing API.

Registered inventory blocks are protected from regular breaking, explosions, Carry On pickup and placement that changes their inventory pairing. Private contents live in server-side chunk storage and are absent from tile update packets. The original physical inventory remains available as a shared automation buffer after its generated source contents have been transferred to private storage. Hoppers interact with that buffer. Player loot and deposits use their private menu inventory.

Stop the game or server and back up the entire world before migrating or removing the mod. Include playerdata, level.dat, region files and every dimension. Keep them together when restoring. Managed containers share a physical automation buffer. Each player’s private slots and the private-menu cursor also have a checkpoint in their player data. New allocations use their original baseline when a chunk save is newer than the player’s first checkpoint. Turning off automatic registration leaves already-managed inventories accessible. Disabling private loot suspends their menus.

## Installing through Gradle

Close the destination game. From the project directory, run the following with a Java 8 JDK. The profile path must contain a mods directory.

```powershell
$instance = (Resolve-Path -LiteralPath (Read-Host 'Full path of the destination profile')).Path
.\gradlew.bat push-to-modpack "-PmodpackDir=$instance"
```

The task builds, runs checks, reobfuscates and stages the new JAR. It verifies the mod ID in matching old JARs and keeps recoverable copies in the profile’s lootr4rlcraft-backups directory. The same task accepts a dedicated server directory. Install the same product JAR on both sides. The optional client and server probe JARs belong only in disposable qualification environments.
